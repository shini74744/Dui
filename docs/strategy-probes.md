# 出口探测、分级故障切换与历史记录

在 **Xray 设置 → 负载均衡** 中配置最低延迟、最低负载、随机、轮询。面板 v26.9.44 起提供分别设置的界面，需要 DUI 核心 vx-26.5 或更新版本；对外发布的 v26.9.46 / vx-26.6 已包含这些功能。

## 策略如何选择出口

| 策略 | 新连接的选择方式 |
| --- | --- |
| 最低延迟 | 根据可用出口的探测结果，选择延迟较低的出口 |
| 最低负载 | 根据探测延迟、波动、失败比例及策略参数筛选候选出口，再进行选择 |
| 随机 | 在候选出口中随机选择 |
| 轮询 | 在候选出口间依次选择 |

最低负载不读取远端服务器 CPU、内存、在线人数或剩余带宽。随机、轮询也不保证各出口承担相同字节数：不同连接的持续时间和流量可能不同。

DUI 核心 **vx-26.8** 起，四种策略均可在不填写 `fallbackTag`（备用出口）的情况下，根据已配置的探测结果排除故障出口：

- 有可用候选出口时，继续按当前策略选择可用出口。
- 全部候选出口不可用时，只使用明确填写的备用出口；要用直连兜底，必须明确选择 `direct`。
- 备用出口留空时，拒绝这组的新连接，探测继续运行；探测确认出口恢复后，自动重新参与分配。不会隐式改走首个出站或直连，也不会把请求无限期挂起。
- 必须启用覆盖候选出口的探测；随机、轮询未配置探测时仍普通分配，尚未得到探测结果的出口也不能视为已确认故障。最低负载原有质量筛选参数继续有效。

旧核心 vx-26.7 及之前，随机和轮询仍需填写备用出口才会过滤故障；全部无可用出口且未填写备用出口时，可能落到默认出口。仅升级面板不会改变核心行为。

故障判断受检测间隔、超时和保留样本影响，不保证即时切换。探测和策略变化不会把已经建立的连接迁移到另一个出口；未命中任何路由规则的流量仍按原有默认出口处理。

## 独立设置的范围

各策略与单独出口分别保存探测参数。核心 vx-26.10 起，相同出口采用相同探测方式、地址、间隔、超时、样本数等参数时，复用同一次探测和结果；参数不同则分别检测。最低延迟与 Burst 探测使用不同方法，不强行合并。

独立的粒度是“策略类型”：多个最低负载组共用最低负载这一套探测设置；不同策略类型使用不同设置。探测出口根据对应类型的负载均衡组选择器合并生成。

面板 v26.9.53 起，四种策略分别通过折叠菜单展开；打开、切换或收起不会改写配置。面板 v26.9.55 起，新安装、没有已有探测设置的新配置默认检测间隔为 1m。升级、编辑和新增使用者始终优先保留用户的独立设置或旧共享设置，不会覆盖用户已保存的间隔。

界面字段名称与说明跟随面板选择的 13 种语言；高级 JSON 中的核心字段名和出口标签保持原样。

| 策略 | 可设置的探测参数 |
| --- | --- |
| 最低延迟 | 探测地址、检测间隔、是否并发 |
| 最低负载、随机、轮询 | 各自的探测地址、平均检测间隔、超时、保留样本数、本机连通性检查地址 |

高级 JSON 可保留额外字段。参数范围：

- 最低延迟的间隔必须为正数。
- 其余三种策略的平均间隔至少 `10s`，超时必须为正数，样本数为 1–1000。
- 时间单位包括 `s` 秒、`m` 分钟、`h` 小时，例如 `30s`、`5m`。
- 本机连通性检查地址可留空；配置后只在出口探测失败时用于检查本机网络。

## 多久探测一次

以页面实际显示并保存的设置为准。旧配置会沿用已有参数，不会因打开页面而自动套用新默认值。

- **最低延迟**：使用检测间隔；开启并发时并发检测各出口，未开启时逐个检测。同一出口的实际周期还受出口数量和探测耗时影响。
- **最低负载、随机、轮询**：间隔是每条出口的平均检测间隔。每个“间隔 × 样本数”窗口内随机安排该出口的多次探测，并非所有出口整点同时检测。

例如平均间隔 `30s`、样本数 `2`，对应约 60 秒的调度窗口内安排 2 次探测；实际时刻有随机性。初始化也会安排探测，用于尽快得到结果。

“保留样本数”用于当前策略计算，和下方历史记录保留多少天是两个独立设置。

## 保存与旧配置兼容

打开页面不会迁移旧配置。编辑某个策略后，其配置写入顶层 `strategyObservatory` 对应的策略名称；未单独修改的策略沿用原有设置。

删除或切换负载均衡策略会更新探测出口；暂未使用的策略保留参数但不探测。出站“同步保存”也会更新这四组引用。

修改先进入页面草稿，点击页面“保存”后才生效。旧核心不能保存独立探测配置；启用后也不能通过面板降级到不支持它的核心。

## 单独路由 Fallback

面板 v26.9.55 / 核心 vx-26.10 起，可在路由规则的“出站 Tag”下选择可选的 Fallback：

- 主出口可用时使用主出口；主出口不可用、备用可用时才使用备用。
- 主出口探测恢复后，后续新连接回到主出口。
- 不填备用或主备都不可用时拒绝新连接，继续探测，等待恢复；不会自动使用默认出口或直连。
- 保存新增或修改的单独出口路由时启用“单独出口探测”。多个单独路由引用同一出口时只保留一个探测目标；黑名单、API 等特殊出口不加入。
- 已有路由不会仅因打开页面而迁移。可编辑路由后保存，或在“负载均衡 → 单独出口探测”修改参数并保存来启用。
- 尚未取得有效探测结果时拒绝新连接。原有连接不会因探测切换而迁移。

## 自定义（分级优先）

添加或编辑负载均衡时选择“自定义（分级优先）”。每一级分别选择实际出口及随机、轮询、最低延迟或最低负载策略，可增加、删除、调整顺序，最多 10 级。

例如第一级 A/B 轮询，第二级 C/D 最低延迟，第三级明确选择 direct。总是从最高可用级选择出口；该级没有可用候选时才进入后一级。未添加直连级且全部失效时拒绝新连接。上一级被探测为可用后，新连接立即优先使用上一级；发现恢复仍受探测周期和保留样本影响。

级别中的出口标签按完整名称匹配，不能用标签前缀代替；传统负载均衡的前缀选择器行为保留。各级使用其策略对应的探测设置；相同出口和参数按上述规则复用探测。

新功能需要核心 vx-26.10 或更新版本。面板会在保存及降级前校验版本，避免旧核心忽略 Fallback 或分级设置。

## 最近探测记录

面板 v26.9.45 与核心 vx-26.6 起支持真实探测历史。可按策略、出口筛选并分页查看：

- 探测时间；
- 出口标签与策略；
- 成功、失败或本机网络不可用；
- 单次探测延迟。

探测列表统一显示时间、出口、结果和延迟，不再附加“旧版共享探测”说明。历史数据继续保留；同一次复用探测的结果可在多个使用它的设置页查看，不能按页面出现次数计算实际探测次数。

面板每 5 秒读取核心新增记录，去重后保存到 SQLite：

| 项目 | 范围 |
| --- | --- |
| 保留时间 | 最近 7 天 |
| 全局条数上限 | 100,000 条；超过时删除最旧记录，因此高频探测可能不足完整 7 天 |
| 核心临时缓冲 | 最多 4,096 条 |
| 重启后 | 已写入数据库的记录保留 |
| 页面刷新 | 只读取历史，不触发新探测，也不改变策略样本数 |

升级前的历史无法补录。面板长时间中断或探测过于密集可能使核心缓冲溢出，界面会提示记录可能不完整；突然断电可能损失尚未收集的数秒数据。

记录只包含必要的探测结果和出口标签，不保存探测 URL、凭据或用户连接地址；查看接口要求面板登录。
