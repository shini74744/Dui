# 出站编辑与同步保存

在 **Xray 设置 → 出站规则** 编辑已被引用的出站时，弹窗会显示关联路由数量及其他引用数量，并提供“确定”和“同步保存”。

## 两种确认方式

| 按钮 | 行为 |
| --- | --- |
| 确定 | 只修改当前出站草稿，不改写其他规则中的出口标签 |
| 同步保存 | 修改当前出站草稿，并把支持的关联引用同步到新标签 |

两种方式都需要最后点击 **页面顶部“保存”** 才会写入配置并生效。关闭弹窗用于取消本次尚未确认的编辑。

出站标签是路由引用的名称。如果只改节点地址、端口、密码或传输参数，标签保持不变，原路由仍然引用这个出站，会在最终保存生效后使用新参数。

## 改名示例

假设已有：

- 出站标签：`HK-A`
- 某条路由：`outboundTag: HK-A`

把出站改名为 `HK-B`：

- 选择“同步保存”：路由引用同时变为 `HK-B`。
- 选择普通“确定”：出站变为 `HK-B`，路由仍引用 `HK-A`；直接点击页面“保存”可能因引用不存在而被拒绝。

先普通确认后，可以在**同一个未重新加载的页面草稿**中，再次编辑该出站，点击“同步保存”补做同步。v26.9.43 起会记住草稿里的连续改名，因此按钮不会因一次普通确认而丢失旧引用。

这些待同步记录只存在于当前页面内存，不写入 Xray 配置，也不跨浏览器刷新保留。同步完成、成功重新加载配置或恢复默认配置后会清理记录。取消编辑或页面保存校验失败不会丢失已有待同步记录。

## 同步范围

- 路由规则中的 `outboundTag`；
- 负载均衡的 `selector` 和 `fallbackTag`；
- 普通探测、Burst 探测的 `subjectSelector`；
- 四种独立策略探测中的 `subjectSelector`；
- 已支持的链式出站引用，包括 `sockopt.dialerProxy`、XHTTP 下载设置中的对应字段及历史 `proxySettings.tag`。

同步只处理明确表示出口标签的字段，不替换节点地址、密码或其他任意文本。它保留路由匹配条件、顺序和自定义 List 来源记录。历史字段被同步不代表当前核心仍接受该旧字段，最终保存仍要通过核心校验。

## 标签和前缀保护

- 标签不能为空、重复，也不能使用系统保留的 `__dui_blacklist_` 前缀。
- 负载均衡和探测选择器可以按标签前缀匹配。同步会保留其他节点的原分组归属；若新标签会意外扩大或改变分组，会拒绝并提示先调整标签或分组。
- 旧标签被其他出站占用时，不会把属于那个出站的引用抢过来。
- 删除出站后不会保留可用于误同步的改名记录。

出站顺序调整与标签改名相互独立，见 [出站排序与默认出口](outbound-order.md)。

## 开发验证

- `node scripts/test-outbound-references.cjs`：引用识别、连续改名、补做同步、前缀分组和旧标签占用等逻辑。
- 页面最终保存仍执行配置验证；错误提示应先修正引用或协议配置，不能通过跳过校验强行保存。
